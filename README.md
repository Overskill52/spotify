# Spotify Playlist Autonomous Backup 🎵🔄

Полностью автономный ежедневный бэкап вашего плейлиста Spotify в этот Git-репозиторий с использованием **GitHub Actions** и **Python**.

Каждую ночь робот автоматически проверяет ваш плейлист. Если в нём появились новые треки или удалились старые — он обновляет файл **`backups/playlist.csv`** и делает коммит в репозиторий.

Файл сохраняется в кодировке `utf-8-sig` (с маркером BOM, поэтому кириллица и спецсимволы корректно и без «кракозябр» открываются в Microsoft Excel).

## ⚡ Быстрая настройка за 5 шагов (подробная инструкция)

Даже если вы никогда раньше не работали с GitHub и кодом, просто следуйте этим шагам по порядку:

---

### Шаг 1. Создайте копию этого репозитория себе

1. В правом верхнем углу этой страницы нажмите кнопку **Fork** (Вилку).
2. Нажмите зелёную кнопку **Create fork**.
3. Теперь у вас есть собственная копия этого проекта в вашем аккаунте GitHub. Все дальнейшие действия выполняйте **в своей копии**!

---

### Шаг 2. Получите бесплатные ключи разработчика Spotify

> 💡 **Лайфхак:** Создать приложение разработчика можно на **любом** аккаунте Spotify (даже на вашем личном бесплатном), не обязательно на том же, где лежит плейлист!

1. Перейдите на официальный портал: 👉 **[Spotify Developer Dashboard](https://developer.spotify.com/dashboard)** и войдите под вашим Spotify-аккаунтом.
   > ⚠️ **Если вверху горит оранжевая полоса «You need to verify your email address...»:**  
   > Нажмите кнопку **Verify** и подтвердите почту по ссылке из письма. Если у вас нет доступа к этой почте (например, аккаунт куплен), нажмите **Update email address** и укажите свою личную почту, либо просто зайдите в Dashboard под своим личным обычным аккаунтом Spotify.
2. В правом верхнем углу нажмите фиолетовую кнопку **Create app**.
3. Заполните форму:
   * **App name**: `Spotify Backup`
   * **App description**: `Daily playlist backup`
   * **Website**: оставьте пустым.
   * **Redirect URIs**: вставьте `https://example.com/callback` и обязательно нажмите кнопку **Add** справа *(протокол должен быть именно `https`, не `http`!)*.
   * **Which API/SDKs are you planning to use?**: поставьте галочку напротив **Web API**.
   * Прокрутите вниз, поставьте галочку согласия с условиями (*I understand and agree...*) и нажмите кнопку **Save**.
4. Откроется страница вашего созданного приложения. Нажмите на вкладку **Settings** (или шестерёнку):
   * Найдите строку **Client ID** — нажмите иконку копирования рядом с ней (два квадратика). Сохраните этот ключ.
   * Чуть ниже нажмите синюю надпись **View client secret** — скопируйте появившийся длинный **Client Secret**.

---

### Шаг 3. Подготовьте ссылку на ваш плейлист

1. Откройте Spotify (на компьютере или телефоне).
2. Откройте нужный плейлист.
   > ⚠️ **Важно:** Плейлист должен быть **публичным (открытым)**:
   > - Нажмите на **три точки `...`** рядом с кнопкой Play.
   > - Если там есть пункт **«Сделать открытым»** (*Make public*) или **«Опубликовать в профиле»** (*Add to profile*) — нажмите его.  
   > *(Если у вас «Любимые треки / Liked Songs» — выделите их все через `Ctrl + A` и добавьте в новый созданный плейлист, так как раздел «Любимые треки» является системной приватной папкой).*
3. Нажмите меню **`...`** ➔ **Поделиться (Share)** ➔ **Скопировать ссылку на плейлист (Copy link to playlist)**.
   * Ссылка выглядит примерно так:  
     `https://open.spotify.com/playlist/37i9dQZF1DXcBWIGoYBM5M?si=...`

---

### Шаг 4. Добавьте ключи в секреты репозитория GitHub

Секреты хранятся в зашифрованном виде внутри GitHub и защищены от посторонних глаз:

1. В вашем репозитории на GitHub перейдите во вкладку **Settings** (в верхней строке меню).
2. В левой боковой колонке найдите раздел **Secrets and variables** и нажмите на **Actions**.
3. Убедитесь, что выбрана вкладка **Secrets** (вверху), и найдите блок **Repository secrets**.
4. Нажмите зелёную кнопку **New repository secret** и добавьте 3 секрета по очереди:

#### Секрет 1 (Client ID):
* **Name**: `SPOTIFY_CLIENT_ID` *(или `CLIENTID`)*
* **Secret**: вставьте ваш Client ID из Шага 2 (без пробелов в начале и в конце!).
* Нажмите **Add secret**.

#### Секрет 2 (Client Secret):
* Снова нажмите **New repository secret**:
* **Name**: `SPOTIFY_CLIENT_SECRET` *(или `CLIENTSECRET`)*
* **Secret**: вставьте ваш Client Secret из Шага 2.
* Нажмите **Add secret**.

#### Секрет 3 (Ссылка на плейлист):
* Снова нажмите **New repository secret**:
* **Name**: `SPOTIFY_PLAYLIST_ID` *(или `PLAYLISTID`)*
* **Secret**: вставьте скопированную ссылку на плейлист из Шага 3 (например: `https://open.spotify.com/playlist/...`).
* Нажмите **Add secret**.

---

### Шаг 5. Разрешите GitHub Actions сохранять файлы (Permissions)

По умолчанию GitHub Actions заблокирован от записи изменений в репозиторий. Разрешим ему сохранять CSV-файл:

1. В том же меню **Settings** вашего репозитория перейдите в левой колонке: **Actions** ➔ **General**.
2. Прокрутите страницу в самый низ до раздела **Workflow permissions**.
3. Переключите тумблер на:  
   🔘 **Read and write permissions** *(Разрешения на чтение и запись)*.
4. Нажмите кнопку **Save** ниже.

## 🚀 Как проверить работу прямо сейчас

Не нужно ждать ночи, чтобы убедиться, что всё работает:

1. В вашем репозитории откройте вкладку **Actions** (в верхнем меню).
2. В левой колонке выберите **Spotify Playlist Backup**.
3. В правой части страницы нажмите кнопку **Run workflow** ➔ зелёную кнопку **Run workflow**.
4. Через 15–20 секунд задача загорится **зелёной галочкой (✔ Success)**!
5. Перейдите на главную страницу репозитория (вкладка **Code**) ➔ зайдите в папку **`backups`** ➔ там появится файл **`playlist.csv`** со всеми вашими треками!

## 📊 Что сохраняется в CSV-файле

Каждый трек сохраняется со следующими метаданными:

| Колонка | Пример значения | Описание |
|---|---|---|
| `Artist(s)` | `The Weeknd, Daft Punk` | Исполнитель (или список через запятую) |
| `Track Name` | `Starboy` | Название трека |
| `Album` | `Starboy` | Альбом |
| `Release Date` | `2016-11-25` | Дата релиза |
| `ISRC` | `USUM71607007` | Международный стандартный номер аудиозаписи |
| `Spotify URL` | `https://open.spotify.com/track/...` | Прямая веб-ссылка на песню |
| `Spotify URI` | `spotify:track:...` | Внутренний идентификатор для приложений |
| `Added At` | `2023-01-15T12:00:00Z` | Когда трек был добавлен в плейлист |

## ❓ Частые ошибки и их решения (FAQ)

<details>
<summary><b>🔴 Ошибка: «Отсутствуют обязательные переменные окружения: ...»</b></summary>

* **Причина:** Вы не создали один из секретов или опечатались в поле `Name`.
* **Решение:** Проверьте вкладку `Settings -> Secrets and variables -> Actions`. В блоке **Repository secrets** должны быть три секрета: `SPOTIFY_CLIENT_ID` (или `CLIENTID`), `SPOTIFY_CLIENT_SECRET` (или `CLIENTSECRET`), `SPOTIFY_PLAYLIST_ID` (или `PLAYLISTID`). В именах не должно быть пробелов!
</details>

<details>
<summary><b>🔴 Ошибка: «Unsupported URL / URI»</b></summary>

* **Причина:** В секрет `SPOTIFY_PLAYLIST_ID` вставлен неверный адрес (например, заглушка, название плейлиста словами или ссылка на альбом вместо плейлиста).
* **Решение:** Откройте плейлист в Spotify -> нажмите `...` -> *Поделиться* -> *Скопировать ссылку на плейлист* и вставьте полученную ссылку в секрет `SPOTIFY_PLAYLIST_ID`.
</details>

<details>
<summary><b>🔴 Ошибка: «error: invalid_client, Invalid client»</b></summary>

* **Причина:** Spotify не узнал Client ID или Client Secret.
* **Решение:** Скопируйте заново `Client ID` и `Client Secret` со страницы вашего приложения в [Spotify Developer Dashboard](https://developer.spotify.com/dashboard) и обновите секреты в GitHub. Убедитесь, что не скопировали лишний пробел в начале или конце ключа.
</details>

<details>
<summary><b>🔴 Ошибка: «This redirect URI is not secure» при создании приложения Spotify</b></summary>

* **Причина:** Spotify требует протокол `https://`.
* **Решение:** Укажите `https://example.com/callback` и нажмите кнопку **Add**.
</details>

## ⏰ Расписание работы

- Воркфлоу настроен на автоматический ежедневный запуск в **04:00 UTC** (07:00 по московскому времени).
- Бот использует **умный коммит**: если за прошедшие сутки вы не меняли плейлист, коммит не создаётся и история репозитория не засоряется.
